# Faz 3 — Kimlik ve Lig

Bu faz öncekilerden yapı olarak farklı: ilk kez sunucu tarafı devreye
giriyor. Şimdiye kadar her şey tarayıcıda çalışıyordu ve kimse kimseyle
yarışmıyordu. Lig geldiği anda **puan bildirmek bir hile hedefi** haline
geliyor. Bu yüzden faz, "üyelik ekle" işi değil, "güvenilir puan
altyapısı kur" işi.

Faz ikiye bölündü. 3A bitmeden 3B'ye geçilmiyor.

---

## Önce üç kural

Bunlar sonradan düzeltilmesi çok pahalı olan şeyler.

### Kural 1 — İstemcinin bildirdiği puana asla güvenilmez

Şu an oyun puanı tarayıcıda hesaplıyor. Lig geldiğinde bu kabul
edilemez: tarayıcı konsolunu açan herkes kendine 9999 puan yazdırabilir.

Doğru akış:

```
İstemci                    Edge Function (sunucu)
   │                              │
   │  tohum + oynanan zincir      │
   ├─────────────────────────────►│
   │                              │ 1. tohumdan turu YENİDEN üretir
   │                              │ 2. zinciri sıfırdan doğrular
   │                              │ 3. puanı KENDİSİ hesaplar
   │       puan + kayıt onayı     │ 4. veritabanına yazar
   │◄─────────────────────────────┤
```

İstemci "15 puan aldım" demiyor; "şu taşları şöyle birleştirdim"
diyor. Sunucu aynı `TurSaglayici` kodunu çalıştırıp kendi kararını
veriyor. Aynı mantık iki yerde çalıştığı için `paketler/oyun-sayi`
hem tarayıcıda hem Edge Function'da kullanılabilir olmalı.

### Kural 2 — Misafir geçmişi lige işlemez

Üye olan misafirin ilerlemesi devralınacak, yoksa kimse üye olmaz.
Ama devralınan veri **tarayıcıdan geliyor**, yani uydurulabilir.
Birisi localStorage'a sahte bir yıl doldurup lig birincisi olarak
başlayabilir.

Ayrım şu:

| Devralınan | Lige işler mi |
|---|---|
| Seri, tam isabet sayacı, 28 günlük şerit, kişisel istatistik | ✅ evet |
| Lig puanı | ❌ hayır |

Lig, üye olunduğu günden itibaren başlar. Kişisel geçmiş korunur,
sıralama temiz kalır.

### Kural 3 — Günlük tabloya o günün EN İYİ maçı yazılır

Toplamı değil. Bu tek kural, çok oynayanın değil iyi oynayanın
kazanmasını sağlıyor ve farm'lamayı öldürüyor. Haftalık ve aylık
tablolar, günlük en iyilerin toplamından oluşur.

## Faz 3A — Kimlik ve güvenilir kayıt

### Yapılacaklar

**Supabase projesi**
- Bölge: Frankfurt (`eu-central-1`) — Türkiye'ye en yakın
- Ücretsiz katman şimdilik yeterli; lansmanda Pro'ya geçilecek

**Veritabanı şeması**

```sql
-- Oyuncu profili. auth.users'a bağlı.
oyuncu(
  id            uuid primary key,      -- auth.users.id
  kullanici_adi text unique not null,  -- lig tablosunda görünen ad
  gorunen_ad    text,
  olusturuldu   timestamptz default now(),
  son_gorulme   timestamptz
)

-- Her doğrulanmış tur sonucu. YALNIZCA Edge Function yazar.
tur_sonuc(
  id           bigserial primary key,
  oyuncu_id    uuid references oyuncu(id) on delete cascade,
  oyun         text not null,          -- 'sayi' | 'kelime'
  mod          text not null,          -- 'gunun' | 'antrenman'
  seviye       text not null,
  tarih        date not null,
  tohum        bigint not null,
  uzaklik      int not null,           -- 0 = tam isabet
  puan         int not null,
  sure_sn      int not null,
  adim_sayisi  int not null,
  joker_sayisi int not null,
  olusturuldu  timestamptz default now(),
  unique(oyuncu_id, oyun, mod, tarih, tohum)   -- aynı tur iki kez yazılamaz
)

-- Misafirken biriken kişisel geçmiş. Lige işlemez.
devralinan_gecmis(
  oyuncu_id uuid references oyuncu(id) on delete cascade,
  veri      jsonb not null,
  devralindi timestamptz default now()
)

-- Denge değerleri kodda değil burada dursun ki
-- yeni sürüm yayınlamadan ayarlanabilsin.
ayar(anahtar text primary key, deger jsonb)
```

**Satır düzeyi güvenlik (RLS)** — bu adım atlanırsa herkes herkesin
verisini değiştirebilir:

| Tablo | Okuma | Yazma |
|---|---|---|
| `oyuncu` | herkes (lig ve profil için) | yalnızca kendi satırı |
| `tur_sonuc` | herkes | **hiç kimse** — sadece Edge Function (service role) |
| `devralinan_gecmis` | yalnızca sahibi | yalnızca Edge Function |
| `ayar` | herkes | hiç kimse |

**Üyelik**
- E-posta ile giriş (sihirli bağlantı ya da şifre)
- Google ile giriş
- **Misafir oynamaya devam eder** — üyelik hiçbir yerde zorunlu değil
- Kullanıcı adı seçimi: 3–16 karakter, Türkçe harf serbest, benzersiz,
  küfür/hakaret filtresi

**Misafir → üye geçişi**
- Üye olunca tarayıcıdaki geçmiş `devralinan_gecmis` tablosuna yazılır
- Seri, tam isabet sayacı ve 28 günlük şerit korunur
- Lig puanı devralınmaz (Kural 2)
- Kullanıcıya açıkça söylenir: "Geçmişin taşındı. Lig puanların
  bugünden itibaren birikmeye başlıyor."

**Sunucu tarafı doğrulama**
- `tur-gonder` Edge Function: tohum + zincir alır, turu yeniden üretir,
  zinciri doğrular, puanı hesaplar, yazar
- Aynı tur ikinci kez gönderilirse reddedilir
- Günün turu günde bir kez — sunucu tarafında da kontrol edilir
  (istemcideki kilit sadece arayüz kolaylığı, gerçek kilit sunucuda)

**Ortam değişkenleri**
- `VITE_SUPABASE_URL` ve `VITE_SUPABASE_ANON_KEY` → Cloudflare Pages
  ortam değişkenlerine
- **Service role anahtarı asla depoya girmez**, yalnızca Supabase Edge
  Function gizli değişkeni olarak durur

### Faz 3A kabul kriteri

- Üye olmadan oyun eskisi gibi çalışıyor
- Üye olunca misafir geçmişi taşınıyor, hiçbir şey kaybolmuyor
- Günün turu oynanınca sonuç sunucuya yazılıyor
- **Tarayıcı konsolundan sahte puan gönderilince sunucu reddediyor**
  (bu bir testle kanıtlanmalı)
- Aynı günün turu ikinci kez gönderilemiyor
- Çıkış yapıp tekrar girince geçmiş duruyor
- Antrenman sonuç ekranındaki oturum toplamı belirgin bir kart olarak
  görünüyor ve üye olmayana "puanların kalıcı olur" notu çıkıyor

## Faz 3B — Lig ve profil

### Yapılacaklar

**Lig tabloları**

```sql
lig_gunluk(
  tarih     date,
  oyun      text,
  seviye    text,
  oyuncu_id uuid,
  en_iyi_puan int,        -- o günün EN İYİ maçı, toplamı değil
  primary key(tarih, oyun, seviye, oyuncu_id)
)

lig_donem(
  donem_tipi  text,        -- 'hafta' | 'ay'
  donem_anahtar text,      -- '2026-W34' | '2026-08'
  oyun text, seviye text,
  oyuncu_id uuid,
  toplam_puan int,
  gun_sayisi  int,
  primary key(donem_tipi, donem_anahtar, oyun, seviye, oyuncu_id)
)
```

- `tur_sonuc`'a yazma anında tetikleyici (trigger) günlük tabloyu
  günceller: yeni puan mevcut en iyiden büyükse değiştirir
- Günlük en iyiler haftalık ve aylık toplamlara eklenir
- **Seviye başına ayrı tablo** — "3 hanede en çok yapan", "4 hanede en
  çok yapan" ayrı ayrı

**Lig ekranı**
- Sekmeler: Günlük / Haftalık / Aylık
- Seviye seçici
- İlk 100 sıra, kendi sıran her zaman görünür (100'ün dışındaysan
  listenin altında ayrıca gösterilir)
- Dönem bitimine kalan süre

**Profil sayfaları**
- `/o/kullanici-adi` — herkese açık, arama motorlarına açık
- İstatistikler: seri, tam isabet sayısı, seviye bazlı en iyi puanlar,
  son 28 gün şeridi
- Bu sayfalar SEO yüzeyi: oyuncular kendi profillerini paylaştıkça
  organik trafik gelir

**Yasal metinler**
- KVKK aydınlatma metni
- Gizlilik politikası
- Çerez politikası
- Kullanım koşulları
- Hesap ve veri silme talebi mekanizması (KVKK zorunlu)

> **Uyarı:** Bu metinlerin taslağı hazırlanabilir ama **bir avukata
> okutulmadan yayına alınmamalı.** KVKK'da eksik aydınlatma metni idari
> para cezası konusu. Üyelik açılmadan önce hazır olmalı.

### Faz 3B kabul kriteri

- Günün turunu oynayınca adın ilgili seviyenin günlük tablosunda çıkıyor
- Aynı gün ikinci kez oynayamıyorsun, dolayısıyla tablo şişmiyor
- Haftalık tablo, günlük en iyilerin toplamını gösteriyor
- Profil sayfası açılıyor ve paylaşılabiliyor
- Yasal metin sayfaları erişilebilir
- Hesap silme talebi çalışıyor
